# Figure provenance

Separate original-problem figure/caption, solution figure/reference, extracted
structured geometry, and optional rendered illustration. Only source-visible
facts can be trusted source geometry. If an essential diagram is missing and
text does not determine the task, defer `missing_diagram_information` with the
specific needed labels/topology, instead of using the supplied solution to guess.
If text suffices, proceed and record figure absence as nonblocking.

P11's Fig.237 caption gives qualitative mirror/screen/upright-segment/ray placement.
It does not give h,l,α, shadow endpoints or l≥h*tan α. Fig.494 is solution-only.
Choose coordinates/parameters explicitly, derive ray intersections and the regime
boundary, prove both cases with witnesses. Never store a derived regime as source
evidence. Keep upright/inverted reflected-light loss distinct from direct-channel
blockage and full darkness.

If rendering a schematic, generate it from a separate source-only geometry file.
Record rendering coordinates, ray count and inclination as drawing choices, not
measurements. A deterministic `--check` mode can verify regeneration. Do not
claim independent image/caption verification unless it was actually performed.
P04 demonstrates caption-derived explicit graph connectivity; P10 derives areas
from caption vertices rather than accepting solution areas. P07 explicitly records
unauthorized visual-reference influence in its historical illustration: do not
promote that image to a clean caption-only gold result. P11 is the preferred
provenance regression.

Figures are optional output artifacts. Do not reconstruct a solution diagram
and call it the original problem. Keep solution-reference files separately labeled
and out of trusted generator inputs and problem premises.
